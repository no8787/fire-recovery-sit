## 3. 구현된 기능

### 공개 영역

- Supabase Auth 기반 로그인, 역할(`super_admin` 등) 검증
- 프로젝트/카테고리/게시글/FAQ CRUD, 문의 상태 관리

- 모든 변경은 `activity_logs`에 기록

### `imports/` 를 둔 이유

원본 사진 111장(180MB)이 `public/images/소머리국밥/`에 있었다. 이 상태로 두면:
1. URL에 상호명이 그대로 노출된다 (상호 비공개 원칙 위반)
2. 원본 180MB가 git 히스토리와 Vercel 배포에 통째로 실린다

따라서 `imports/`로 옮기고 `.gitignore`에 등록했다.
**게시용 이미지는 반드시 선별·리사이즈하고 익명 슬러그를 붙여 `public/images/` 아래에 별도로 배치한다.**

## 6. 구조적 주의사항 (수정 시 반드시 확인)

### 6-1. 공개 페이지에서 쿠키 기반 Supabase 클라이언트 금지 ★

`generateStaticParams`를 쓰는 페이지(SSG)나 정적 페이지에서
`@/lib/supabase/server`(쿠키 바인딩 클라이언트)를 호출하면
**`"Page changed from static to dynamic at runtime"` 오류로 500이 발생한다.**

- 공개 페이지 조회는 반드시 `createPublicClient()` (`src/lib/supabase/public-client.ts`) 사용
- 쿠키 클라이언트는 `/admin` 등 세션이 필요한 곳에서만 사용

**이 오류는 `next dev`와 `npm run build`에서는 재현되지 않는다.**
반드시 `npm run start`(로컬 프로덕션 모드)로 검증할 것. (사고 이력: `64a9c06`)

### 6-2. 이미지 경로 이원화 — 정적 경로 vs Storage

`project_images.storage_path`에는 두 종류의 값이 섞여 들어올 수 있다.

| 형태 | 예시 | 출처 |
|---|---|---|
| 정적 경로 | `/images/construction/<slug>/0.jpg` | 초기 시드 데이터 (127행 전부 현재 이 형태) |
| Storage 오브젝트 키 | `<uuid>/<filename>.jpg` | 관리자 화면 업로드 |

`src/lib/supabase/public-queries.ts`의 `resolveImageSrc()`가 이를 구분한다.

```ts
// "/" 또는 "images/"로 시작하면 정적 파일 경로로 통과시키고,
// 그 외에는 Storage public URL로 변환한다.
```

- 현재 Supabase Storage `project-images` 버킷은 **비어 있다**(0개).
  시드 이미지는 DB 레코드만 있고 실제 파일은 `public/images/construction/`에 있다.
- 이 분기를 제거하면 기존 27건 이미지가 전부 깨진다. **절대 단순화하지 말 것.**
- 새 외부 도메인 이미지를 쓸 경우 `next.config.ts`의 `images.remotePatterns` 등록 필요.

### 6-3. 정적 페이지 재검증

홈(`/`)은 완전 정적 페이지다. 관리자에서 데이터를 바꿔도
`revalidatePath("/")`를 호출하지 않으면 **재배포 전까지 절대 갱신되지 않는다.**

재검증 경로는 `src/lib/revalidate-public.ts` 한 곳에서 관리한다.
공개 페이지 구성이 바뀌면 이 파일의 경로 목록도 함께 갱신할 것. (사고 이력: `731c745`)

### 6-4. 콘텐츠 원칙

- **확인되지 않은 수치·실적·인증을 만들지 않는다.** 모든 회사 정보는 지명원(2025-10-14) 근거.
- **과장·오해 소지 표현 금지**: "긴급출동", "즉시출동", "골든타임", "24시간 상담 접수",
  "업계 최고", "100% 보장" 등. 카카오 버튼의 "24시간 채팅상담"만 예외적으로 허용.
- AI 생성 이미지와 실제 시공사진을 같은 그리드에 섞지 않는다.
  AI 이미지는 공정 설명용, 실제 사진은 실적 증거용으로 역할을 분리한다.
- `src/lib/data/fire-recovery-examples.ts`의 예시 콘텐츠는 실제 사례가 아니며
  "AI 생성 예시 이미지" 배지가 항상 노출된다.
